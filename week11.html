01

Can a computer read a heart?

About a million ECGs are recorded every day worldwide. Recording one is simple; interpreting it is hard for humans and machines alike. Since the 1950s computers have helped, first with hand-written rules and now with deep learning trained on millions of examples. This week's talks show what that looks like in practice, and what can go wrong.

  • LO1Describe how data science and ML are used in cardiology, and the challenges.
  • LO2Compare rule-based and machine learning approaches to the same problem.
  • LO3Use sets, logic, functions, matrices and graphs, and their R equivalents.
  • LO4Classify variables as nominal, ordinal or metric.
  • LO5Read JSON and web data, time code and use multiple cores in R; know what Shiny is for.
02

Data science in cardiology

Heart failure in Northern Ireland

Heart failure is common, increasing, under-detected and still deadly (around 39% mortality at one year in national audit data). A doctoral study combined a systematic review, open government data (QOF, NISRA), survival analysis (Kaplan–Meier, Cox regression: Week 4), supervised ML (decision trees) and unsupervised ML (PCA and k-means: Week 8) to map the landscape and find patient phenotypes.

What the review found

Many published ML papers overclaim clinical usefulness, and about a quarter were written by IT specialists without clinical input. Lesson: domain experts belong on the team, and a good AUC is not the same as a useful tool.

AI for ECGs

A Belfast start-up built a database of over a million ECGs for algorithm development. Deep networks now match or beat individual cardiologists on several tasks, e.g. a residual network on 90,000+ single-lead ECGs (Hannun et al., 2019) and networks trained on 2 million 12-lead ECGs that outperformed resident doctors on six abnormalities (Ribeiro et al., 2020).

Data requirements

Large (thousands of examples or more), clean (correct labels: a single annotator makes errors, so use consensus) and diverse (many edge cases, many populations). Labels are the expensive part, which is why unsupervised learning on unlabelled ECGs is attracting interest.

03

Rule-based versus machine learning

A rule-based system uses rules written by experts: preprocess, detect beats, correct the baseline, average beats, apply decision logic. When it fails you can see why. A machine learning system learns the rules from many labelled examples; it can find patterns no one wrote down, but the reasoning is hidden. The explorer is a simple rule: "a beat is wherever the signal crosses a threshold". Add noise or baseline wander and watch the rule break.

Number systems and scientific notation

Explorer

Scientific notation (as R prints it)

R prints 1.23e-05 for 1.23 × 10⁻⁵, but 0.000123 stays as it is because the fixed form is no longer than the scientific one. You saw this with p-values (Week 3) and 2¹⁰⁰ = 1.27e+30 (Week 9). format(x, scientific = FALSE) turns it off.

Sets and logic

Explorer

Set operations and their R functions

Explorer

Truth tables

Compare "NOT (P AND Q)" with "NOT P OR NOT Q": identical columns. That is De Morgan's law. In R: expand.grid(P = c(TRUE, FALSE), Q = c(TRUE, FALSE)) then compute the column. You use these every time you subset() with & and |.

06

Functions: domain, codomain and range

A function f : A → B assigns exactly one element of B to each element of A. A is the domain, B the codomain, and the elements actually reached form the range (image). Every model in this module is a function: features in, prediction out.

Not functions

A mapping where one input has two outputs (2 → 4 and 2 → 5) is not a function; nor is one that leaves an input with no output. In R, function(x) x^2 is a function in exactly this sense, and sqrt() has domain x ≥ 0 for real numbers (try sqrt(-1)).

A function is one-to-one (injective) if different inputs always give different outputs, and onto (surjective) if the range is the whole codomain. x² on A is neither.

07

Matrices

An m × n matrix has m rows and n columns: exactly how a data frame of numbers is stored. A distance table is a symmetric matrix (aij = aji); dist() in Week 8 built one. Matrix multiplication is behind regression (X %*% beta), PCA (X %*% rotation) and every layer of a neural network (W %*% x + b).

Explorer

Matrix multiplication step by step

Element (i, j) of A·B is row i of A times column j of B, summed. The inner sizes must match: (m × n)(n × p) gives m × p. In R use %*%; plain * multiplies element by element.

08

Graphs and networks

A graph has vertices (nodes) and edges; in a directed graph (digraph) edges are arcs with a direction. A network is stored as an adjacency matrix: mij = number of arcs from i to j. Squaring the matrix counts the paths of length 2. Social networks, process maps (Week 12) and association-rule graphs (Week 9) are all graphs.

09

Statistics and variable types

Descriptive statistics summarise a sample (the class's mean height); inferential statistics generalise from the sample to the population (the university's mean height). The type of each variable decides which summaries, plots and tests are valid.

Explorer

Sort the variables

Nominal: categories with no order (in R a factor). Ordinal: ordered categories (factor(..., ordered = TRUE)). Metric: numbers on a scale (numeric), discrete counts or continuous measurements.

The R toolkit: what to reach for next

Web pages: rvest, xml2

Web scraping: read a page's HTML and pull out elements by CSS selector.

library(rvest)
webpage <- read_html("https://www.ulster.ac.uk")
html_node(webpage, "title") %>% html_text()
JSON: jsonlite

The format of most web APIs. Data frames go to JSON as an array of records and come back unchanged; car names travel in a "_row" field. Note toJSON() keeps only 4 decimal places unless you set digits.

library(jsonlite)
j <- toJSON(mtcars, pretty = TRUE)
myCarDataset <- fromJSON(j)
Big files: data.table

fread() reads CSVs many times faster than read.csv() and guesses separators and types.

library(data.table)
myDataset <- fread("data.csv")
Timing and cores

system.time() measures code; parallel (built into R, no install needed) runs work on several cores.

system.time(rnorm(1e6))
library(parallel); detectCores()
mclapply(1:8, slow_fn, mc.cores = 4)
Networks: statnet, igraph

Social network analysis: degrees, centrality, communities.

Dashboards: Shiny

Interactive web apps written only in R: inputs, reactive outputs, plots. Try shiny::runExample("01_hello"). Big data: sparklyr connects R to Apache Spark.

Explorer

JSON round trip

Records (one object per row) are the default and what most APIs send. The column form is more compact; this site's charts use it for the data they load.

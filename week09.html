Association Rule Mining

Which things happen together? Association rules turn lists of transactions (shopping baskets, symptoms, web pages visited) into "if this, then that" rules. You will measure rules with support, confidence and lift, see why the apriori algorithm is needed, and mine 9,835 real grocery baskets in R.

01

What goes together?

A supermarket records every basket. Researchers at Ulster used store transaction data to see how shopping changed during the COVID-19 pandemic (Boyle et al., 2022), and the same method found which reasons for calling a crisis helpline tend to occur together (Turkington et al., 2020). Nobody states a hypothesis first: the algorithm searches every combination and reports the ones that co-occur more than chance would predict. That is hypothesis-free knowledge discovery, done in minutes rather than days.

  • LO1Describe transactional data and write an association rule as LHS ⇒ RHS.
  • LO2Calculate support, confidence and lift by hand and interpret them.
  • LO3Explain why the number of itemsets explodes and how the apriori property prunes the search.
  • LO4Mine, sort, filter and inspect rules with arules; visualise them with arulesViz.
  • LO5Judge whether a rule is trivial, actionable or inexplicable.
02

Transactions, itemsets and rules

Transaction

One record holding a set of items, of any size: {bread, milk, eggs}, {geneA, geneB}, {cough, chest pain, high BP}. There are no columns of numbers, so arules uses its own transactions class, not a data frame (see read.transactions()).

Rule

{milk, eggs} ⇒ {bread}. The left-hand side (LHS, antecedent) is what is in the basket; the right-hand side (RHS, consequent) is what tends to come with it. A rule is a co-occurrence, not a cause.

Applications

Market basket analysis, product and film recommendations, co-morbidities, symptoms that co-occur, web pages visited before a purchase, patterns in DNA and protein sequences.

Unsupervised

Like clustering, there is no target variable. Any item can appear on either side of a rule; the algorithm decides which rules are interesting from the data alone.

03

Support, confidence and lift

Support

How often an itemset occurs.
support(X) = count(X) / N
The support of a rule X ⇒ Y is the support of X and Y together.

Confidence

How often the rule is right when the LHS is present.
conf(X ⇒ Y) = support(X ∪ Y) / support(X)
This is the conditional probability P(Y | X).

Lift

How much more likely Y is when X is present than in general.
lift(X ⇒ Y) = conf(X ⇒ Y) / support(Y)
1 = independent, > 1 = together more than chance.

A filled square means the item is in that basket. Rows with the LHS are outlined; rows that also contain the RHS are shaded. Confidence counts only the outlined rows; lift compares that with how common the RHS is overall.

In the lecture example, {milk} has support 2/3 = 0.67, and the rule {milk} ⇒ {bread} also has support 0.67 because both baskets with milk contain bread. Its confidence is 0.67 / 0.67 = 1. Lift = 1 / support(bread) = 1 / 0.67 = 1.5.
04

What lift really measures

A rule can have high confidence and still be useless. In the Groceries data, 25.6% of all baskets contain whole milk, so any rule ⇒ {whole milk} will be right about a quarter of the time by chance. Lift divides that chance away. The explorer shows 100 baskets: each square is a basket, shaded if it contains Y, outlined if it contains X.

Explorer

100 baskets: confidence against chance

Try X = 15, Y = 26, both = 4: confidence 0.27 looks reasonable, but lift ≈ 1, so X tells you nothing. Then set both = 11 (roughly honey ⇒ whole milk): lift ≈ 2.8.

lift > 1

X and Y occur together more than expected if independent. Positive association: worth a look.

lift = 1

Independent. Knowing X changes nothing about Y, however high the confidence.

lift < 1

Together less than expected: substitutes (people who buy one brand avoid another).

05

Why we need the apriori algorithm

With k items there are 2k possible itemsets. A small shop with 100 products has 2100 ≈ 1.27 × 1030; the Groceries data has 169 items. We can't count them all. The apriori property saves us: every subset of a frequent itemset must also be frequent. So if {batteries} is rare, no itemset containing batteries can be frequent, and we never need to count {batteries, apples}.

Apriori works level by level: count single items, keep the frequent ones, build pairs only from those, count, keep the frequent pairs, build triples, and so on. Then, from the frequent itemsets, it keeps the rules whose confidence passes the threshold.

07

Mining and exploring rules

rules <- apriori(Groceries, parameter = list(support = 0.001, confidence = 0.25, minlen = 2))
rules                                   # set of 17391 rules
inspect(rules[1:20])
inspect(sort(rules, by = "lift")[1:10])
inspect(subset(rules, rhs %in% "whole milk" & lift > 3))

minlen = 2 stops rules with an empty LHS such as {} ⇒ {whole milk}. Lower support or confidence gives many more rules: at support 0.01 there are only 170. The explorer holds the rules with support ≥ 0.003 and confidence ≥ 0.1 (up to 4 items), so you can filter and sort them live.

Explorer

Filter, sort and inspect rules

Like plot(rules) from arulesViz: each dot is a rule; darker dots have higher lift. The highest-lift rules tend to have low support: rare but strong combinations. Click a row to highlight its dot.

08

Checking lift by hand

The first rule from inspect(rules[1:20]) is {honey} ⇒ {whole milk}: support 0.00112 (11 baskets), confidence 0.7333, lift 2.870. Honey is in 15 baskets and 11 of them also contain whole milk.

Confidence

11 / 15 = 0.7333
73% of honey baskets contain whole milk.

Support(whole milk)

2513 / 9835 = 0.2555
26% of all baskets contain whole milk.

Lift

0.7333 / 0.2555 = 2.870
Honey buyers are 2.9 × as likely as an average shopper to buy whole milk.

supp_milk <- itemFrequency(Groceries)["whole milk"]   # 0.2555
q <- quality(rules[1])
q$confidence / supp_milk                              # 2.870009, matches q$lift
# check all 20 at once
r20 <- rules[1:20]
rhs_supp <- itemFrequency(Groceries)[unlist(LIST(rhs(r20)))]
all.equal(quality(r20)$confidence / rhs_supp, quality(r20)$lift, check.attributes = FALSE)
09

Is the rule any use?

Mining is the easy part; the thousands of rules need domain expertise. Lantz suggests sorting rules into three kinds.

Trivial

Obvious to anyone in the business: {flour, sugar} ⇒ {baking powder}; {nappies} ⇒ {baby food}. True but no new knowledge.

Actionable

Clear, useful and new: {herbs} ⇒ {root vegetables} (lift ≈ 3.9) suggests placing them together or a joint promotion.

Inexplicable

No obvious reason; could be chance, a promotion that month, or a data artefact. Needs investigation before anyone acts on it.

Watch out. (1) With support 0.001 a rule can rest on 10 baskets: rare rules are noisy. (2) Mining thousands of rules guarantees some high lifts by chance (the multiple-testing problem from Week 3). (3) A rule is co-occurrence, not causation: putting honey next to milk won't necessarily sell more milk.

Key terms

TermMeaning
TransactionOne record: a set of items (a basket, a patient's symptoms).
ItemsetAny set of items, e.g. {milk, bread}.
LHS / RHSAntecedent and consequent of a rule X ⇒ Y.
SupportProportion of transactions containing the itemset.
Confidencesupport(X ∪ Y) / support(X) = P(Y | X).
Liftconfidence / support(Y): how much X raises the chance of Y.
Coveragesupport(X): how often the rule can be applied.
Apriori propertyAll subsets of a frequent itemset are frequent; used to prune the search.
Strong ruleHigh support and high confidence.
